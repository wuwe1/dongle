# 接到车上

## 硬件（DIY，大约 50 元）

- **ESP32-C3 SuperMini**（拇指大，自带 USB-C，最接近"U 盘"）或 **ESP32-S3-DevKitC**（引脚多，好调试）。
  要带**原生 USB** 的型号（S3/C3）：固件把日志走芯片自己的 USB，一辆车的总线每秒几千帧，115200 的串口只够 250 行/秒。
- **SN65HVD230 CAN 收发器模块**（3.3V）。⚠️ 很多模块板上焊了一个 **120Ω 终端电阻**（常标 R2），
  **接车之前拆掉**：车的总线两端已经有终端了，再并一个会改变总线阻抗——这是 listen-only 也挡不住的电气影响。
- **OBD-II 公头/转接线**。

现成的替代（不用焊）：市面上有 ESP32 做的开源 OBD 加蓝牙/WiFi 小盒子（例如 MeatPi 的 WiCAN）。这个固件
只要改 `main/Kconfig.projbuild` 里的两个引脚就可能能刷上去——**引脚要按它的原理图核对，我没查证过**。

## 接线

| ESP32 | 收发器 | OBD-II |
|---|---|---|
| GPIO5（`DONGLE_CAN_TX_GPIO`） | TXD / CTX | |
| GPIO4（`DONGLE_CAN_RX_GPIO`） | RXD / CRX | |
| 3V3 | 3V3 | |
| GND | GND | 4 或 5（地） |
| | CANH | 6 |
| | CANL | 14 |

**v0 不接 OBD 的 16 号脚（常电 12V）**：ESP32 由电脑的 USB 供电。这样不用处理 12V 降压，
也不会在车熄火后偷偷耗电瓶。电脑用电池供电最干净（避免车载逆变器充电带来的地环路）。

## 奔驰要先知道的：网关

较新的奔驰（大致 2015 年后的平台）的 OBD 口挂在**中央网关**后面：OBD 上那条 CAN 是**诊断总线**，
网关默认不把车身总线的广播（门锁、车窗、灯……）转到这里。所以第一次插上可能出现两种结果：

1. **有大量周期性的帧** → 网关在转发（或者你的车型 OBD 上就是车身/动力总线），可以直接嗅探按键。
2. **几乎安静**，固件反复打印 `bus silent at every bitrate` → 被网关挡住了。下一步有两条路，都要先讨论：
   - **主动诊断请求**（UDS/OBD-II 读数据，比如 0x22 ReadDataByIdentifier）：网关会放行，但这意味着**要发帧**，
     不再是 listen-only，需要专门加一个有物理开关保护的发送路径。
   - **物理上接到网关后面的车身 CAN**（拆内饰找线）：仍然只读，但动手量大。

具体是哪种，取决于车型和年份。

## 第一次实验（停车、熄火或 ACC，不开车）

1. 电脑接 ESP32 的 USB，`cat /dev/cu.usbmodem* | tee first.log`；手机连 BLE `dongle`。
2. 插 OBD，点火到 ON（不启动发动机）。看日志开头：`listening at 500000 bit/s`？还是 `bus silent`？
3. 如果有帧：手机发 `mark idle`，**什么都不碰等 20 秒**（基线越长，滚动计数器越不会被误报）。
4. 发 `mark lock`，按一次遥控锁车键或车内锁门键，等 3 秒；`mark done`。可以重复几轮（`mark unlock` 等）。
5. `python3 tools/canlog.py diff first.log --base idle --action lock`，把输出连同 `summary` 一起交给 Claude 看。

## 安全与法律

- v0 只读：硬件 listen-only + 固件不含发送代码。拆掉收发器上的 120Ω 电阻后，它对总线就只是一个高阻抗的旁听者。
- **以后加任何发送功能**：只在停车时测试；要有物理开关才能启用；永远不在行驶中注入。
- 读懂自己车的总线属于正常的维修和研究。但**绕过付费的联网服务**（比如远程锁车订阅）可能违反服务条款，
  不同地区的法律界定也不一样；改动车辆电子系统还可能影响质保。做到哪一步，由你自己判断。
